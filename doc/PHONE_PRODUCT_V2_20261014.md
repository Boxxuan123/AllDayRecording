# 手机端产品化 V2 — 2026-10-14

本轮只重做今天、回忆、事项及共用证据详情。以实机 1.0.14 截图和本地提交 `bd5281672e78c8247a88bf52a19c23f190960d05` 为基线；版本提升到 1.0.15 / 1000015。Web 内容改版留待后续。

## 内容与组件

| 页面 | 具体变化 | 原业务复用 |
|---|---|---|
| 今天 | 两条有依据的回顾重点；区分本人、他人、听到的内容；当天缺少回顾时使用最近可用历史内容；展开时间线；可直接打开最近录音；紧凑覆盖状态 | PhoneDailyCache、原日回顾/会话、原提醒/跟进投影 |
| 回忆 | 搜索优先；提交后进入结果；人物/来源/时间/分析折叠；原文结果、归纳失败和不完整覆盖用用户语言显示；处理上限等信息折叠 | historyRecall 的 query/page/context/cancel，原来源身份管理 |
| 事项 | 一个卡片入口；当前本人、等待对方、已安排提醒、线索、已结束；历史承诺不默认算今日待办；详情才展开原话和适用动作 | 原 reminder.task、chat.followup、outbox/revision、Calendar Kit |
| 证据详情 | 来源/时间/发言人/原话/前后文；录音按原位置播放及打开完整转写；返回保留查询；技术字段折叠 | 原查询上下文、按 ID 转写读取、播放器及录音页面 |

UI 映射没有写入新的业务状态。相同 Event 的聊天跟进与提醒去重；无提醒的跟进不假装通知已安排。已结束事项保留原定时间和来源，不再提示需要执行。日历失败、权限和外部修改使用原重试接口；恢复外部修改的按钮明确说明按事项时间恢复。

原底部四入口、录音/人工标注、人物安全纠正、审核箱、同步/备份与管理路由保留。没有添加假最近查询；现有回忆接口没有可合法读取的持久化查询历史入口。

## 数据及验收边界

全部完成、修改、取消等写操作均在独立 SQLite/RDB 与合成来源中执行。实机隔离装配运行生产页面、UseCases、Repository 和原生 AVPlayer，但使用测试 Remote 和合成静音 WAV；静音音频只验证定位及播放生命周期，不表示文字对应真实语音。

生产手机数据库的 DB/WAL/SHM/DWR/compare 五个文件，在所有隔离实机验收前后 SHA-256 一致。只在设备内计算哈希，没有导出生产数据库。真实数据核对只通过现有页面与只读回忆接口，不改变人工状态、任务、日历或人物关系。

保存的聊天引用需要先建立现有 API 的查询上下文。组合查询只覆盖引用前后各一秒，关闭模型与后续扩展，且精确匹配记录 ID 后才读原消息；资料缺失/失效/离线均保留保存的原话并提示。普通搜索沿用后端检索能力，未启用归纳时显示原文结果；长句中的泛词可能使检索范围变宽，可用引号限定主题或折叠筛选中的精确关键词。

本轮没有真实模型调用，没有聊天全历史扫描，没有生产业务写入。模型按用户选择和电脑配置处理必要资料，可能联网，并非统一声称完全离线。
