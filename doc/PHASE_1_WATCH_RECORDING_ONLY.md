# Phase 1A：手表本地录音 PoC

> 文档状态：`superseded` — AAC/M4A 单文件 PoC 已被当前连续 PCM/WAV 生产录音链替代。

## 目标

在不依赖手机、Wear Engine、配对状态或跨设备权限的前提下，只验证手表端本地录音能力：

1. 首次点击录音时请求麦克风权限。
2. 使用手表麦克风录制单声道 AAC 音频。
3. 停止后在应用沙箱生成非空 M4A 文件。
4. 页面显示实际录制时长与文件大小。
5. 在手表端本地试听刚刚生成的文件。

本轮应用仅声明 `wearable` 设备类型。原 Wear Engine 传输实现保留在仓库中，但不被当前页面和清单引用，也不属于本轮验收范围。

## 录音参数

- 容器：M4A
- 编码：AAC
- 采样率：16 kHz
- 声道：单声道
- 码率：64 kbps
- 保存位置：应用沙箱 `filesDir`
- 文件名：`watch_<时间戳>.m4a`

## 真机测试步骤

1. 将当前签名 HAP 安装到 API 23 或更高版本的 HarmonyOS 手表。
2. 启动“全天录音”，确认页面显示“录音仅保存在手表本地”。
3. 点击“开始录音”，首次运行时允许麦克风权限。
4. 对手表说一段包含清晰数字或短句的内容，持续 10–15 秒。
5. 点击“停止录音”，确认页面显示时长、非零文件大小和“录音已保存到手表，可本地试听”。
6. 点击“本地试听”，确认能听到刚才的内容；播放结束后状态变为“播放完成”。
7. 再录制一次不同内容，确认时长和大小更新，并且试听的是第二次录音。

页面针对圆形手表采用状态互斥布局：录音完成后不再同时展示“开始录音”，而是把“本地试听”放在圆屏中央安全区，“重新录音”作为下方次要操作。

## 验收标准

- 授权麦克风后能进入录音状态，计时每秒递增。
- 连续录制 10–15 秒后能正常停止，应用不崩溃。
- 生成的 M4A 文件大小大于 0，页面展示的时长与实际录制时长基本一致。
- 本地试听能辨认录入的语音内容；停止播放和播放完成状态正确。
- 点击“本地试听”后，标题切换为“正在试听”，主按钮切换为“停止播放”，证明点击事件已进入播放流程。
- 第二次录音不会误用第一次录音的页面状态或播放内容。

## 熄屏持续录音 PoC

第一轮先执行 10 分钟可控验证，不直接宣称数小时稳定：

1. 重新安装当前 HAP，打开应用并开始录音。
2. 确认页面显示“持续录音已启动，可以熄屏”。
3. 说出“开始标记”和当前时间，然后让手表正常熄屏；不要强制关闭应用。
4. 保持熄屏 10 分钟，中途在第 5 分钟和结束前各说一次时间标记。
5. 亮屏返回应用，停止录音。
6. 确认显示时长不少于 10 分钟，文件大小随录制时间明显增长，并能开始本地试听。

工程在录音开始后申请 `AUDIO_RECORDING` 持续任务，停止或启动失败时撤销持续任务。计时使用录音开始时间与当前时间的差值，避免熄屏期间 JavaScript 定时器暂停造成显示时长偏短。

## 明确不验收

- Wear Engine 服务与权限审批。
- 手机/手表配对和在线状态。
- 手机端安装、接收或播放。
- P2P 文件传输、失败提示、传输大小上限。
- 主动关闭应用后的录音、进程被杀后的恢复、重启续录、超过本轮 10 分钟的稳定性、录音历史列表和文件导出。

## 证据边界

构建通过只能证明 ArkTS 编译、资源处理和 HAP 打包成功，不能证明麦克风采集或本地播放成功。最终结论必须以手表真机按上述步骤完成一次录音与试听为准。

## 当前验证状态（2026-08-24）

- 已完成一次清理后的 Debug 构建，ArkTS 编译、资源处理、HAP 打包与签名成功。
- 用户报告已经完成一次约 150 分钟的单文件长时录音，长时间采集获得正向证据；该结果尚不代表自动分段连续性已经通过。
- 当前工程进入 Phase 1B：使用 5 秒/10 秒高频轮换和固定参考音，客观测量相邻 M4A 的毫秒级间隙，详见 `PHASE_1B_WATCH_SEGMENT_GAP_TEST.md`。
- 打包后的模块清单仅包含 `wearable`，只申请 `ohos.permission.MICROPHONE`，不包含 Wear Engine 的 Client ID 元数据。
- 编译产物中未发现 Wear Engine、发送到手机或手机接收页面相关字符串。
- 构建仍提示 AVRecorder/AVPlayer 并非所有设备都具备的系统能力；代码已添加运行时能力检查，最终是否支持必须由目标手表确认。
- 当前在线 USB 设备被识别为 `phone`，已登记的无线调试端点均离线，因此没有向手机安装，也尚未完成手表真机录音与试听验收。
- 用户在手表首轮操作中反馈“试听听不了”，旧页面在录音完成后同时显示过多控件，试听按钮位于圆屏下半部。页面现已改为状态互斥的圆屏布局，并为播放态增加明确的标题、按钮和媒体音量提示；圆屏修正版真机截图确认按钮点击有效。
- 圆屏修正版真机截图随后确认按钮点击有效，但播放返回 `5400102`。本地 SDK 定义该错误为播放器状态不允许操作：设置 `fdSrc` 后必须等待 AVPlayer 从 `idle` 异步进入 `initialized`，才能调用 `prepare()`。播放服务现已改为等待 `initialized` 后再依次执行 `prepare()` 和 `play()`。
- 播放器状态机修正版已完成 Debug 构建、覆盖安装并成功启动。自动短录音验证被手表通知页面覆盖和无线调试掉线打断，实际出声结果仍需在手表前台重新录制后确认。
