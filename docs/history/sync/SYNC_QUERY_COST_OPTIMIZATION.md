# 手机同步重复开销优化（2026-09-27）

## 行为变化

- 每批最多查询 32 条资源与依赖均就绪的操作，SQL 筛选、排序并限制数量。
- 每批回执统一清理一次；回执、投影、覆盖层和游标原子提交。
- 全量转写按会话建立索引，每条 JSON 只解析一次。正常批次按变化的 utterance ID 刷新，并保留并发到达的增量。
- 审核、人物以内容版本跳过重复写入；重启客户端后仍按落库内容去重。审核变化单独刷新审核列表，复用转写对象。
- 手机 schema 11 → 12，只新增 outbox 创建时间索引。

## 验证

- Hypium：Phone 75/75；Phone/Watch 合计 142/142。
- 9 组同步专项测试通过，覆盖持久化操作、依赖、并发刷新、延迟投影、64 KiB 上限和回滚。
- 新增 `tools/quality/check-sync-query-cost.cjs`：21 会话/2,100 条转写只解析 2,100 次；1,200 条队列只解析返回的 32 条；32 回执清理一次；相同审核/人物版本零行写入、零刷新通知。
