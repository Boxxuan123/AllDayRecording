# 项目目录约定

| 位置 | 用途 |
| --- | --- |
| `entry/` | Watch HAP 源码与模块测试 |
| `phone/` | Phone HAP 源码与模块测试 |
| `common/` | 跨设备共享 HAR 源码与模块测试 |
| `AppScope/`、`hvigor/` | 应用元数据和构建声明 |
| `contracts/` | 两端共享契约与版本凭据 |
| `tests/` | 跨模块、集成与设备验证 |
| `tools/` | 开发、诊断、验收和运维脚本；分类见工具索引 |
| `docs/architecture/` | 当前架构与边界 |
| `docs/guides/` | 使用和调试说明 |
| `docs/engineering/` | 工程维护计划与目录规范 |
| `docs/features/` | 功能设计 |
| `docs/history/` | 历史实验、阶段报告和验收证据 |
| `outputs/` | 可重新生成的输出；由命令按需创建并被 Git 忽略 |

根目录保留 README、许可、构建/依赖/配置文件与必要启动入口。新文档按主题进入 docs；不要把实验报告放到源码或工具目录。源码按现有模块边界演进，避免为整理目录改变导入路径。

历史记录用于追溯，不代表当前实现或最新验收结果。当前行为先核对架构、源码和共享契约。工具旁用于解释测试夹具的 README 继续与夹具放在一起。

临时 worktree 放到项目外的专用目录，完成后先保存未提交内容、确认提交可达，再通过 Git 移除。输出中的真实录音、数据库、私有配置和独有备份必须先迁出保存；不能使用 git clean -fdx 批量清理。
